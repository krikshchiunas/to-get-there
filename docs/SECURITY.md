# Безопасность

Как устроена защита To Get There, как она проверена и что остаётся сделать
руками в панелях сервисов.

## Модель

Права решает база, а не приложение. Любое действие идёт через клиент Supabase
с сессией пользователя, и политики RLS (`supabase/migrations/0008_rls.sql` и
дальше) решают, можно ли. Серверный код только объясняет отказ по-человечески.

Исключение одно: вебхук Stripe приходит без сессии и записывает итог проверки
личности серверным ключом через `apply_verification_result()` — вызвать её
может только `service_role`.

## Что защищено и чем

| Что | Чем | Где |
|---|---|---|
| Чтение без входа | `open_read = false`, у `anon` нет прав на данные | 0014 |
| Чужие строки | RLS на всех таблицах | 0008, 0010, 0020 |
| Внутренние функции через API | вынесены в схему `private`, PostgREST её не публикует | 0024, 0026 |
| Исключённый модератор | роль снимается триггером, права требуют членства | 0016 |
| Точка автора в режиме радиуса | огрубляется до ~1 км триггером в базе | 0022 |
| Документы для проверки личности | не хранятся: их собирает Stripe | 0019, 0020 |
| Подделка вебхука | HMAC-SHA256 подписи, окно 5 минут, лимит тела | `app/api/webhooks/stripe` |
| Чужой путь в `avatar_url` / `media_url` | только свои пути из Storage | `lib/media.ts` |
| Загрузка в чужую папку | политики `storage.objects` | 0009 |
| GPS-координаты в фото | картинка перерисовывается до загрузки | `lib/upload.ts` |
| Открытый редирект после входа | `safeNext()` | `lib/safe-next.ts` |
| Подмена Host в ссылках из писем | адрес из настроек, не из запроса | `lib/site-url.ts` |
| XSS | CSP с nonce на каждый запрос, без `unsafe-inline` для скриптов | `lib/csp.ts`, `middleware.ts` |
| Кликджекинг | `frame-ancestors 'none'`, `X-Frame-Options: DENY` | `next.config.ts` |
| Чужой личный канал Realtime | политика на `realtime.messages`: только свой `user:<id>` | 0018 |

Каждая строка таблицы проверена: тестами (`npm test`) или вживую на базе —
попыткой сделать запрещённое и проверкой, что база отказала.

## Советник Supabase

Было 25 замечаний, из них одно уровня ERROR. Осталось одно — защита от
утёкших паролей (см. ниже), это настройка панели, а не код.

## Зависимости

`npm audit`: было 10 уязвимостей (2 критических), осталось 5 высоких — все в
одной цепочке `eslint-config-next → @next/eslint-plugin-next → fast-glob →
micromatch → braces`. Это отказ в обслуживании на глубоко вложенных шаблонах
путей. Работает только когда линтер разбирает наши же файлы, в сборку и к
пользователям не попадает. Исправленной версии `braces` нет — ждём её или
обновления плагина Next.

PostCSS принудительно обновлён до исправленной версии и внутри Next
(`overrides` в `package.json`).

## Сделать руками

- **Supabase → Authentication → Providers → Email → Prevent use of leaked
  passwords.** Сверяет пароль с базой утёкших (HaveIBeenPwned). Доступно на
  платном тарифе.
- **Supabase → Authentication → URL Configuration.** Site URL — адрес
  продакшена; Redirect URLs — `https://<домен>/auth/callback` и
  `http://localhost:3000/auth/callback`.
- **Supabase → Storage → verification.** Пустой бакет без политик, остался от
  0009 — Supabase не даёт удалить его из SQL. Можно удалить кнопкой.
- **Vercel → Settings → Environment Variables:** `SUPABASE_SECRET_KEY`,
  `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` — только для проверки
  личности, без префикса `NEXT_PUBLIC_`.
